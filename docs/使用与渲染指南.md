# 使用与渲染指南

## 查看作品与动画

用 Blender 5.2.1 LTS 打开 `donut_studio.blend`。鼠标移到模型区域，按 **Z → 渲染**，然后按**小键盘 0**进入摄影机视图。没有小键盘时，可点击视图右侧的摄像机按钮。

在底部时间轴的当前帧框输入帧数：

| 帧 | 画面 |
|---:|---|
| 1 | 草莓糖霜初始状态，310 粒动画糖粒还未显现；盘边静态糖粒已经存在 |
| 65 | 糖粒分批落下，部分已经落到表面 |
| 110 | 表面逐渐铺满，空中仍有下落的糖粒 |
| 170 | 310 粒动画糖粒全部落定，适合拍摄完成效果 |
| 192 | 动画结束，相机收尾 |

空格播放／暂停，中键拖动旋转观察，Shift + 中键平移，滚轮缩放。自由观察不会修改渲染摄影机；若主动启用了“锁定相机到视图”，则另当别论。按 F12 渲染当前帧，F11 查看或隐藏渲染结果。

## 编辑模型

右上角 Outliner 按内容分组：

| 集合 | 内容 |
|---|---|
| `01 Pastry` | 面包体和草莓糖霜 |
| `02 Falling sprinkles` | 310 粒具有独立关键帧的动画糖粒 |
| `03 Table styling` | 餐盘、金边、静态糖粒和面包屑 |
| `04 Studio` | 摄影棚背景、灯光、相机和对焦目标 |

选中物体后，G 移动、R 旋转、S 缩放；右键或 Esc 取消当前变换。保存自己的版本可使用“文件 → 另存为”。

糖粒同色实例共享网格，但运动关键帧彼此独立。它们按预先设计的落点运动，不会自动碰撞新修改的糖霜。大幅修改形状后，需要重新调整糖粒落点和轨迹。

## 用 Blender 界面渲染

主工程已包含所有几何、材质、灯光与关键帧。没有外部贴图，也不要求 MCP。

先渲染第 170 帧检查效果，再决定是否输出动画。当前保存的设备设置针对 NVIDIA GPU；若其他电脑不能使用该设备，可在 Cycles 渲染设置中选择本机可用的设备或 CPU。手动渲染的参数可能与下述历史优化脚本不同。

动画输出区间为 1–192、24 fps。README 的预览对应 960 × 800 动画，下载页的高清静帧为 1440 × 1200。

## 原制作脚本的运行范围

这些脚本记录了制作时的实际流程，不是跨平台安装程序：

| 入口 | 依赖与行为 |
|---|---|
| `render.ps1` | 原 Windows 电脑的一键渲染入口，使用 `E:/anaconda3/envs/llm/python.exe` |
| `scripts/benchmark_render.py` | 调用 `E:/Blender/blender.exe`，完整重新计算 192 帧，采样资源占用并编码视频 |
| `scripts/render_frames.py` | 在 Blender 中运行，要求可用的 NVIDIA OptiX GPU；没有可用设备时停止 |
| `scripts/encode_video.py` | 使用已有 192 张 PNG 编码视频并完整解码验证，可单独运行 |
| `scripts/build_donut.py` | 经 MCP 在指定工程中重建；含原机器项目路径，会清空当前目标场景并覆盖主工程 |
| `scripts/finalize_delivery.py`、`package_delivery.py` | 原电脑交付流程，依赖本地报告、图片及未随仓库发布的 MCP 安装说明和环境快照 |

运行制作脚本前要修改本机路径，并准备对应输入；直接运行打包入口或在新电脑上一键重建可能因缺少本地记录而失败。使用发布的 `.blend` 查看、编辑或通过 Blender 界面渲染不受这些脚本依赖影响。

外部 Python 的渲染监测和视频编码使用 `psutil`、`imageio-ffmpeg`，可选 MCP 客户端另使用 `mcp`。Blender 内的 `bpy` 由 Blender 自带。不要把安装历史中的整套 Python 环境清单当成查看模型的必需依赖。

原电脑运行方式：在项目目录执行 `./render.ps1`。它会新建 `cache/frames/<批次>/` 与 `reports/<批次>/`；成功后更新 `output/sugarfall.mp4` 和本机交付材料。CPU 线程设为 8、编码线程设为 4，进程采用较低优先级。此流程会重新渲染，不是播放现成视频。
